#2 The FX vol stack builds forwards without the spot-date adjustment that FxForwardCurve applies (open since the 22nd review) Medium
sdevpy/volatility/fx/fxvolcalib.py · lines 76–77  ·  fxvolinterpolation.py · line 241  ·  fxdeltastrike.py · lines 361, 409  ·  sdevpy/calibration/fx/fxforward.py · lines 20, 23

Why it's bad: FxForwardCurve.load_calibrated first converts the quoted spot to its t = 0 equivalent, spot0 = spot / df_f(spot_date) * df_d(spot_date), and returns spot0 * df_f(T) / df_d(T). The calibrator (fwd = self.spot * df_f / df_d), the surface interpolation and strike_from_delta all use the quoted spot directly. The two differ by df_d(spot_date) / df_f(spot_date), the rate differential over the spot lag. The stored 'fwd' of each tenor defines the surface's moneyness axis, so a pricer that takes its forward from CalibrationDataSet.get_fxforwardcurve reads every smile slightly off-centre.

Fix: convert the spot once, where the calibrator fetches market data (and the same where FxVolInterpolation receives its spot). Add fx_spot_date to the fxdates import:

# t = 0 equivalent of the quoted spot, as in FxForwardCurve.load_calibrated
sdate = fx_spot_date(self.date, self.forccy, self.domccy)
self.spot = self.spot * self.domcurve.discount(sdate) / self.forcurve.discount(sdate)

Then add a test asserting report['fwd'] == calib.get_fxforwardcurve(pair, mkt).value(settlement) for each tenor.

#3 model_time gives different times for the same dates depending on input type, so with an intraday valuation date bond flows and curve nodes are one day apart Medium
sdevpy/utilities/timegrids.py · lines 165–177  ·  sdevpy/rates/bonds.py · lines 78–79  ·  sdevpy/calibration/rates/yieldcurve.py · lines 99, 103  ·  sdevpy/calibration/bonds/bondcurve.py · line 83

Why it's bad: The new datetime64 branch truncates both ends to calendar days. The datetime branch takes timedelta.days, which floors the exact interval. Reproduced with valdate = 2026-10-26 15:00 and the date 2027-10-26: model_time(valdate, datetime) = 0.99726, but model_time(valdate, np.datetime64('2027-10-26')) = 1.0. Bond pay and settlement times go through the datetime64 branch, while InterpolatedYieldCurve.set_data and the fitter's node_times use lists of datetime. A curve fitted to bonds is then stored on a time axis one day off from the flows it was fitted to. Intraday valuation dates are supported by design: DATETIME_FORMAT stores hours, minutes and seconds.

Fix: use one rule for every input type. Since all callers are date-based, count whole calendar days (timegrids.py:167–177):

d1, d2 = np.asarray(date1), np.asarray(date2)
if d1.dtype.kind == 'M' or d2.dtype.kind == 'M': # numpy datetime64: vectorized
    ...
spans = d2 - d1
...
d1 = np.asarray(date1, dtype='datetime64[D]')  # datetime, date, datetime64, or lists of them
d2 = np.asarray(date2, dtype='datetime64[D]')
t = (d2 - d1).astype(np.float64) / 365.0
return float(t) if t.ndim == 0 else t

Fix the annotation at the same time: date1, date2: dt.date | np.datetime64 | Sequence | npt.NDArray. Snapshot tests whose valuation dates carry a time of day may move slightly, which is the intended correction.

sdevpy/volatility/impliedvol/models/tssvi1.py · lines 39, 142  ·  tssvi2.py · lines 34, 130  ·  sdevpy/utilities/tools.py · line 21

Why it's bad: The signature is isequal(a, b, tol=EPS), so isequal(chi, tol) asks whether chi equals 1e-6. Reproduced: isequal(0.0, 1e-6) is False, so chi = 0 enters the extremum check it was meant to skip. Small-tau parameters are then rejected and the optimizer sees an infinite objective in a valid region.         if is_ok and not isequal(chi, tol):
        if is_ok and not isequal(chi, 0.0, tol):

            return np.full_like(k, np.nan)
            return np.full(np.shape(k), np.nan)
#5 InterpolatedYieldCurve.set_data checks for past dates before sorting, so an unsorted input with a past pillar is accepted (open since the 23rd review) Medium

Why it's bad: Line 86 tests dates[0] <= self.valdate with the comment "Assuming the dates are sorted", but the function sorts on lines 89–91. Reproduced: pillars [2026-12-15, 2025-06-15] with valuation date 2025-12-15 are accepted, and the curve keeps a pillar at negative time. #6 The LV section calibrator never checks whether the optimizer converged (open since the 22nd review) Medium
sdevpy/volatility/localvol/lvsection_calib.py · lines 119–133, 152

Why it's bad: After least_squares or optimizer.minimize, the code takes result.x (line 130), writes it into the local vol and moves on to the next expiry. result.success is never read. Each expiry starts from the previous one's density, so a single unconverged section degrades every later one. The returned dict has no convergence flag, so the examples save the result either way. The new bond fitter does this properly (bondcurve.py logs a warning when result.success is false).

Fix: add converged = [] before the loop, then after line 130:

        if not result.success:
            log.warning(f"{name}: LV calibration did not converge at expiry {exp_idx}: {result.message}")
        converged.append(bool(result.success))

and at line 152:

    return {'lv': lv, 'iv_data': surface_data, 'pde_vols': pde_vols, 'history': obj_builder.get_history()}
    return {'lv': lv, 'iv_data': surface_data, 'pde_vols': pde_vols, 'history': obj_builder.get_history(),

#10 Equity path-dependent payoffs default to the US federal holiday calendar, not the exchange calendar Low
sdevpy/montecarlo/payoffs/basic.py · lines 235, 465  ·  sdevpy/montecarlo/payoffs/exotics.py · lines 15, 74

Why it's bad: cdr="USD" maps to holidays.US, the federal holidays. NYSE trades on Columbus Day and Veterans Day. Reproduced: 12-Oct-2026 is a business day on XNYS and a holiday on USD. Daily fixing schedules for variance swaps and Asian or barrier payoffs therefore drop observation days, which changes the realised-variance return count and the averaging. The bond work in this period already shows the right pattern: a market calendar per instrument (USGOV, JPGOV, CAGOV).

Fix: default to the exchange calendar, which make_calendar already resolves through pandas_market_calendars:

    def __init__(self, name, start, end, freq="1D", cdr="USD"):
    def __init__(self, name, start, end, freq="1D", cdr="XNYS"):

Better still, make cdr a required argument, so the underlying's exchange is always chosen explicitly. Regression values for these payoffs will move; that change is intended.
