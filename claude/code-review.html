#1 The Monte-Carlo local-vol lookup still cannot create a new model for any real underlying — hardcoded test names, then a TypeError High
sdevpy/calibration/provider.py · lines 31, 45–47, 57–59, 72  ·  sdevpy/volatility/localvol/localvol_factory.py · lines 10–16

Verified: read the current files and reproduced with get_local_vols(['SPX'], …, CalibrationDataFileProvider(), model_name='VSVI')

Why it's bad: The 17th review's fix made the "no stored file" branch reachable, but the branch itself cannot run. get_local_vols (line 72) calls get_localvol_or_new without a t_grid, and the fallback then calls lvf.get_localvol_new(None, model_name) → create_sections(None, …), which does for t in t_grid. Running it against a name with no stored file gives TypeError: 'NoneType' object is not iterable — while the function's own docstring promises "an error is thrown", i.e. a meaningful one. Without model_name, the lookup uses a map of the three test-fixture names: 

name_model_map = {'ABC': 'BiExp', 'KLM': 'VSVI', 'XYZ': 'Matrix'}   # provider.py:31 — fixture names in production code

so any real ticker raises ValueError: No model name specified for name: SPX (reproduced). Together, the "or new" half of price_book's local-vol resolution works only for the three names that ship with the unit tests.

Fix: Fail with a clear message when there is nothing to load and no grid to build from, and move the name→model map out of production code (into config or the test suite):

def get_localvol_or_new(name, date, model_name, cal_prov, t_grid=None, force_new=False):

        raise ValueError(f"No model name specified for name: {name}")

    if lv is None:

sdevpy/tests/test_mc.py · lines 38, 62  ·  sdevpy/montecarlo/payoffs/exotics.py · lines 26–44, 49–69

Why it's bad: The only test touching the class prices WorstOfBarrier(['ABC','XYZ'], expiry, 90.0, 'Call', 35.0) with spots 100 and 50. #5 implied_vol_brent minimises a squared error over an open bracket — infeasible prices return a plausible-looking vol Medium
sdevpy/analytics/black.py · lines 43–58 (and its use as the low-vega fallback at line 116)

Verified: ran the function — implied_vol_brent(1.0, 80, True, 100, 15.0) (call price below its intrinsic value of 20) returns 1.0e-06; a price of 1e-12 on a 200-strike call returns 1.0e-06; no error either time

Why it's bad: minimize_scalar(error, bracket=(xmin, xmax), method='brent') is a minimiser given a two-point bracket, which is only a starting hint — Brent may leave [xmin, xmax], and res.x is returned without checking res.success or that the residual is near zero. When the price is outside the no-arbitrage range there is no root, and the function still returns a number (1e-6 above). Because implied_vol_newton hands every low-vega strike to this function, the worst cases — deep OTM strikes — are exactly the ones that flow unchecked into calibration targets.

Fix: Bracket a genuine root of the price difference and validate the price first:

from scipy.optimize import brentq

def implied_vol_brent(expiry, strike, is_call, fwd, fwd_price, vmin=1e-6, vmax=10.0):
    lo = price(expiry, strike, is_call, fwd, vmin) - fwd_price
    hi = price(expiry, strike, is_call, fwd, vmax) - fwd_price
    if lo > 0 or hi < 0:
        raise ValueError(f"Price {fwd_price} outside the Black no-arbitrage range for K={strike}, T={expiry}")
    return brentq(lambda v: price(expiry, strike, is_call, fwd, v) - fwd_price, vmin, vmax, xtol=1e-12)

#8 Variance keeps a stale current_fixing when the payoff is re-valued on another date Medium
sdevpy/montecarlo/payoffs/basic.py · lines 474, 507–528

Why it's bad: self.current_fixing = None is set only in __init__. set_valuation_date resets current_sum on every call but assigns current_fixing only inside if hist_fixings is not None and len(hist_fixings) >= 1. A trade object priced first on a late valuation date (with history) and then on a date at or before the variance start (no history) keeps the earlier fixing. evaluate() then executes the "add current increment" branch (line 489–491) and adds log(S₁ / old_fixing)² to a brand-new variance swap. Payoff objects are stateful and set_valuation_date is called on them at every pricing run, so re-using a built book across valuation dates is a natural use, and the resulting PV is wrong without any error.

Fix: Reset all state at the top of set_valuation_date:

    def set_valuation_date(self, valdate, md: MarketDataProvider):
        self.current_sum = 0.0
        self.current_fixing = None
        self.eventdates = []
        hist_fixing_dates = []

and add a test that prices one Variance instance on a late date, then on start, and compares with a freshly built instance.

#10 price_vanilla_surface lacks the short-expiry guard that price_vanillas has Low
