#3 load_learning_model still passes constructor kwargs KerasLearningModel.__init__ doesn't accept Medium
sdevpy/machinelearning/keras/learningmodel.py · line 129 vs. line 14

Why it's bad: Now that predict_on_scaled is implemented (fixed), this is the next thing that will actually surface for anyone loading a model with saved scalers:

def __init__(self, base_model):  # one parameter
model = KerasLearningModel(keras_model, is_scaled=True, x_scaler=x_scaler, y_scaler=y_scaler)

Raises TypeError: __init__() got an unexpected keyword argument 'is_scaled'. The base class's set_scalers(x_scaler, y_scaler) — referenced by the constructor's own comment ("Now need to call set_scalers() instead") — is the intended replacement, but was never applied here.

Fix:

model = KerasLearningModel(keras_model, is_scaled=True, x_scaler=x_scaler, y_scaler=y_scaler)
model = KerasLearningModel(keras_model)
model.set_scalers(x_scaler, y_scaler)

#7 download_file swallows every failure and returns silently Medium
sdevpy/llms/gpt/gpt.py · lines 166-214, called from download_gpt2 lines 132-154

Why it's bad: Every failure branch — primary URL fails, backup URL fails, or an unexpected exception — just print()s and lets the function return None implicitly. download_gpt2 calls it in a loop without checking the return value, so a failed download for any of the 7 required files surfaces later as a confusing "file not found" instead of a clear error at the point of failure.

Fix: Raise on failure (or return a success flag the caller actually checks) instead of printing and continuing.

#8 fbsabr.price's parameters is typed as list[float] but used as a dict everywhere Medium
